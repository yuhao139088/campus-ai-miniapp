# 技术实现说明

架构详见docs/architecture.md，API详见docs/api.md。

- 原生小程序TypeScript：七页、官方custom-tab-bar目录、真实AppID、统一会话及API客户端。
- Node22服务：Express、Zod输入校验、JWT、Multer图片限额与签名校验、请求限流、精确CORS和统一错误。
- 模型编排：OpenAI-compatible适配，最多四轮只读工具调用、90秒总预算，模型输出通过结构校验；模型失败明确降级。
- 数据：PostgreSQL十表，固定主键和user_id索引，JSONB保存结构化Agent结果；迁移可追溯。所有业务对象在应用层归属校验。
- 材料：图片在受控后端识别并上传私有pgstore，文件名使用生成ID；前端不获得服务Key或公开材料URL。
- 表单：服务字段白名单映射，必填、联系方式、日期先后等规则校验。确认后才允许关联到办理任务。
- 前端动效：小程序扫描线、处理中状态、资料导入进度、资格核验结果和任务进度过渡。
- 工程：依赖锁文件、Docker双服务、CI、单元/集成测试、页面结构检查与资源来源清单。

部署模式：本地JSON用于无云凭据复现，CloudBase SQL为实际云存储模式。模型、云服务和微信凭据不进入Git。正式部署前需真实身份、合法HTTPS域名与订阅通知授权，当前无学校生产系统写权限。
